# 窗口联动架构说明

本文档描述当前代码中**窗口之间联动**的实现方式：架构组成与具体函数调用链。

---

## 一、整体架构

窗口联动采用 **事件总线（Event Bus）** 模式：

- **事件类型与载荷** 在 `FCEventTypes.h` 中统一定义。
- **事件总线** 提供 `emitEvent(type, data)` 与信号 `eventReceived(type, data)`，由 APP 层实现（`FCAppEventBus`）。
- **源窗口**（如工程树）不直接依赖目标窗口，只通过总线 **发出事件**。
- **目标逻辑**（如属性面板更新）不依赖源窗口，只 **订阅总线**，根据 `eventType` 和 `data` 执行相应逻辑。

这样任意多个 Docking 窗口都可以通过“发事件 / 收事件”联动，扩展时只需增加事件类型或订阅者。

```
┌─────────────────┐     emitEvent(type, data)      ┌──────────────────┐
│  源（如工程树）   │ ──────────────────────────────▶│   FCIEventBus     │
│  FCProjectTree   │                                 │  (FCAppEventBus)  │
└─────────────────┘                                 └────────┬─────────┘
                                                              │
                                                              │ eventReceived(type, data)
                                                              ▼
┌─────────────────┐     showContent(docking, nodeId) ┌──────────────────┐
│  目标（属性面板） │ ◀────────────────────────────────│  订阅者（操作器）  │
│  FCPropertyWidget│                                 │ FCPropertyPanel  │
└─────────────────┘                                 │ Operator +       │
                                                     │ ContentHandlers  │
                                                     └──────────────────┘
```

---

## 二、核心组件与职责

| 组件 | 文件 | 职责 |
|------|------|------|
| **事件类型与载荷键** | `FCInterface/FCEventTypes.h` | 定义 `FCAppEventType`、`PropertyPanelEntityType` 及 `EventPayloadKey_*`，约定事件语义和 payload 结构。 |
| **事件总线接口** | `FCInterface/FCIEventBus.h` | 抽象接口：`emitEvent(int, QVariantMap)`、信号 `eventReceived(int, QVariantMap)`。 |
| **事件总线实现** | `APP/FCAppEventBus.cpp` | 实现 `emitEvent`：内部 `emit eventReceived(eventType, copy)`，把事件发给所有已连接槽。 |
| **总线创建与暴露** | `APP/FCAppUI.cpp` | 在 `createUi()` 中 `mEventBus = new FCAppEventBus(this)`；`getEventBus()` 返回给外部。 |
| **树→总线桥接** | `APP/FCAppController.cpp` | 连接工程树信号到 lambda，在 lambda 里组装 `QVariantMap` 并调用 `bus->emitEvent(...)`。 |
| **属性面板协调者** | `FCActionsOperator/FCPropertyPanelOperator.*` | 订阅 `eventReceived`；收到 `EventTreeNodeSelected` 按 `entityType` 查表调用对应 Handler 的 `showContent`；收到 `EventNoEntitySelected` 清空属性窗口。 |
| **内容处理器接口** | `FCActionsOperator/IPropertyPanelContentHandler.h` | 接口：`showContent(FCDockingAreaInterface*, FCID)`，由各“类型”的具体 Handler 实现。 |
| **几何内容处理器** | `FCActionsOperator/FCGeometryPropertyContentHandler.*` | 实现几何节点选中时的属性内容：用 `FCGeometryPropertyContentFactory` 创建 BuildBar+InfoWidget，接线后 `propWidget->setContentWidget(container)`。 |
| **几何内容工厂** | `FCActionsOperator/FCGeometryPropertyContentFactory.*` | 根据 `FCGeoOpType` 创建 BuildBar + 对应 *InfoWidget，并完成 InfoWidget 与 GraphPreprocess 的接线。 |

## 三、初始化与接线（谁在何时连上总线）

在 **FCAppController::initialize()** 中完成（约 235–263 行）：

1. **取总线**  
   `FCIEventBus* bus = mCore->getUiInterface()->getEventBus();`  
   （总线在 `FCAppUI::createUi()` 中已创建。）

2. **创建并配置属性面板协调者**  
   - `m_propertyPanelOperator.reset(new FCPropertyPanelOperator(this));`  
   - `m_propertyPanelOperator->setUIInterface(mCore->getUiInterface());`  
   - `m_propertyPanelOperator->setEventBus(bus);`  
   在 `setEventBus` 内会调用 `subscribeToEventBus()`，从而  
   `connect(m_eventBus, &FCIEventBus::eventReceived, this, &FCPropertyPanelOperator::onEventReceived, Qt::UniqueConnection)`。

3. **注册几何 Handler**  
   - `m_geometryPropertyContentHandler.reset(new FCGeometryPropertyContentHandler);`  
   - `m_geometryPropertyContentHandler->setBuildBarGlobalActions({ mActions->actionGeometryModelBuildAll });`  
   - `m_propertyPanelOperator->registerHandler(PropertyPanelEntityGeometry, m_geometryPropertyContentHandler.get());`  
   即：当 `entityType == PropertyPanelEntityGeometry` 时，由几何 Handler 负责显示。

4. **工程树 → 总线**  
   - `FCMainTreeWidget* modelWidget = mDock->getModelBuilderWidget();`  
   - `FCProjectTreeWidget* tree = modelWidget->getTreeWidget();`  
   - `connect(tree, &FCProjectTreeWidget::geometryNodeSelected, this, [bus](FCID nodeId) { ... bus->emitEvent(EventTreeNodeSelected, data); });`  
   - `connect(tree, &FCProjectTreeWidget::noEntitySelected, this, [bus]() { bus->emitEvent(EventNoEntitySelected, QVariantMap()); });`  
   树只发事件，不直接碰属性面板。

## 四、运行时调用链（工程树选中 → 属性面板更新）

### 4.1 用户选中工程树中的几何节点

1. **FCProjectTreeWidget**  
   - 树当前项变化触发 `onSelectionChanged()` → `syncPropertyPanelToCurrentItem()`。  
   - 若当前项为几何实体（`ProjectTree_GeometryEntity`），则  
     `emit geometryNodeSelected(nodeId);`  
   - 文件：`FCGUIWidget/FCProjectTreeWidget.cpp`（约 186–214 行）。

2. **FCAppController 的 lambda（树→总线）**  
   - 收到 `geometryNodeSelected(nodeId)` 后：  
     - 构造 `QVariantMap data`：  
       `EventPayloadKey_NodeId` = nodeId，  
       `EventPayloadKey_EntityType` = `PropertyPanelEntityGeometry`。  
     - 调用 `bus->emitEvent(EventTreeNodeSelected, data);`  
   - 文件：`APP/FCAppController.cpp`（约 251–256 行）。

3. **FCAppEventBus::emitEvent**  
   - `QVariantMap copy = data;`  
   - `emit eventReceived(eventType, copy);`  
   - 文件：`APP/FCAppEventBus.cpp`（约 15–19 行）。

4. **FCPropertyPanelOperator::onEventReceived**（Qt 槽）  
   - 由 `eventReceived` 触发，参数为 `(eventType, data)`。  
   - 直接转发：`onEvent(eventType, data);`  
   - 文件：`FCActionsOperator/FCPropertyPanelOperator.cpp`（约 37–40 行）。

5. **FCPropertyPanelOperator::onEvent**  
   - `eventType == EventTreeNodeSelected` 时：  
     - 从 `data` 取 `EventPayloadKey_NodeId`、`EventPayloadKey_EntityType`。  
     - `handler = m_handlers.value(entityType);`（几何时即已注册的 `FCGeometryPropertyContentHandler*`）。  
     - 若 `handler` 非空：`handler->showContent(dockingArea(), nodeId);`  
   - 文件：`FCActionsOperator/FCPropertyPanelOperator.cpp`（约 42–56 行）。

6. **FCGeometryPropertyContentHandler::showContent**  
   - 用 `docking->getSettingParametersWidget()` 得到属性窗口。  
   - 从全局数据取 `FCGeometryDAGData`，根据 `nodeId` 得到 `FCGeoOpType nodeType`。  
   - 若当前属性窗口已是同类型几何内容，则只调用 `m_contentFactory.updateDAGNode(...)` 更新 DAG 节点。  
   - 否则：  
     - `GeometryPropertyContent content = m_contentFactory.createContent(propWidget, nodeType, dagData, nodeId, docking, m_buildBarGlobalActions);`  
     - `wireBuildBarToOperators(content.buildBar, docking);`  
     - `propWidget->setContentWidget(content.container);`  
   - 文件：`FCActionsOperator/FCGeometryPropertyContentHandler.cpp`（约 82–107 行）。

7. **FCGeometryPropertyContentFactory::createContent**  
   - 创建 `FCGeometryBuildBar` 并注入全局 actions。  
   - 按 `nodeType` 创建对应 *InfoWidget（如 FCCubeInfoWidget）。  
   - 将 InfoWidget 与 GraphPreprocess 连接（`geometryBuilt` / `geometrySequenceBuilt`、`setDAGNode`）。  
   - 返回 `GeometryPropertyContent{ container, buildBar }`。  
   - 文件：`FCActionsOperator/FCGeometryPropertyContentFactory.cpp`。

至此，**工程树选中几何节点 → 事件总线 → 属性面板协调者 → 几何 Handler → 工厂创建内容 → 属性窗口显示** 的整条链路完成。

### 4.2 用户取消选中（或选中非几何项）

1. **FCProjectTreeWidget::syncPropertyPanelToCurrentItem**  
   - 若 `!item` 或 id/type 无效或非几何：`emit noEntitySelected();`  
   - 文件：`FCProjectTreeWidget.cpp`（约 193–213 行）。

2. **FCAppController 的 lambda**  
   - 收到 `noEntitySelected()`：`bus->emitEvent(EventNoEntitySelected, QVariantMap());`  
   - 文件：`FCAppController.cpp`（约 257–259 行）。

3. **FCPropertyPanelOperator::onEvent**  
   - `eventType == EventNoEntitySelected` 时：  
     - `docking->getSettingParametersWidget()->setContentWidget(nullptr);`  
   - 属性面板被清空。  
   - 文件：`FCPropertyPanelOperator.cpp`（约 56–60 行）。

## 五、扩展其他窗口联动（如网格、物理场）

1. **事件与类型**  
   - 在 `FCEventTypes.h` 中已有 `PropertyPanelEntityMesh`、`PropertyPanelEntityPhysics` 等，可按需增删。  
   - 若新联动不经过属性面板，可增加新的 `FCAppEventType` 和载荷键。

2. **树侧发事件**  
   - 在工程树或桥接逻辑中，当选中网格/物理场节点时，构造 `data`（含 `nodeId`、`EventPayloadKey_EntityType` = Mesh/Physics 等），调用 `bus->emitEvent(EventTreeNodeSelected, data)`。  
   - 若树当前只区分“几何 / 非几何”，需在树或桥接里根据节点类型设置正确的 `entityType`。

3. **新增内容处理器**  
   - 实现 `IPropertyPanelContentHandler`（如 `FCMeshPropertyContentHandler`），在 `showContent(docking, nodeId)` 中创建并设置对应属性 UI。  
   - 在 `FCAppController::initialize()` 中：  
     - 创建该 Handler；  
     - 调用 `m_propertyPanelOperator->registerHandler(PropertyPanelEntityMesh, meshHandler)`（或 Physics 等）。

4. **其他窗口订阅总线**  
   - 任意对象（不限于属性面板）均可 `connect(bus, &FCIEventBus::eventReceived, this, &MyClass::onEvent)`，在槽里根据 `eventType`/`data` 更新自己的 UI 或逻辑。  
   - 例如：VTK 选中 domain 后 `emitEvent(EventVTKGeometryDomainSelected, data)`，布尔操作属性面板订阅该事件并显示已选几何 id。

## 六、小结

- **架构**：事件总线（`FCIEventBus`/`FCAppEventBus`）+ 事件类型与载荷（`FCEventTypes.h`）+ 订阅者（如 `FCPropertyPanelOperator` + 各 `IPropertyPanelContentHandler`）。  
- **当前主要联动**：工程树（`FCProjectTreeWidget`）⇄ 属性面板（`FCPropertyWidget`），通过 **EventTreeNodeSelected / EventNoEntitySelected** 与 **FCPropertyPanelOperator + FCGeometryPropertyContentHandler** 实现。  
- **关键函数链**：树 `geometryNodeSelected(nodeId)` → Controller 的 lambda `bus->emitEvent(EventTreeNodeSelected, data)` → `FCAppEventBus::emitEvent` → `eventReceived` → `FCPropertyPanelOperator::onEventReceived` → `onEvent` → `handler->showContent(docking, nodeId)` → `FCGeometryPropertyContentHandler::showContent` → 工厂创建内容 → `propWidget->setContentWidget(container)`。

按上述方式扩展事件类型和 Handler，即可在不改总线与协调者核心逻辑的前提下，增加更多窗口之间的联动。

## 七、复杂度评估与简化建议

### 7.1 当前复杂度是否过高？

**客观情况**：层级较多——事件类型 → 总线 → 树桥接 → 协调者 → Handler 接口 → 具体 Handler → 内容工厂。新人要理清“树选中到属性面板刷新”需要跨多个文件。

**是否“太复杂”取决于目标**：

| 若你的目标 | 当前实现 | 建议 |
|------------|----------|------|
| 只有几何 + 属性面板，且长期如此 | 偏重 | 可简化：树信号直接连一个“属性面板更新器”，不用总线、不用 Handler 注册表 |
| 会有几何 / 网格 / 物理场 / 研究 / 结果等多种树节点，属性面板随选中切换（COMSOL 式） | 匹配 | 保留协调者 + Handler 注册；扩展时只加 Handler + 一行 register，不改协调者 |
| 将来还有 VTK 选 domain → 属性面板、或其它窗口互联动 | 匹配 | 保留事件总线；其它窗口只需发/订事件，不必知道属性面板细节 |

结论：**若确定会做“多类型树节点 + 多窗口联动”，当前实现是合理复杂度；若近期只有几何一种，可以适度简化。**

### 7.2 可选的简化方案（在保留扩展性的前提下）

1. **合并“树→总线”进协调者**  
   - 现在：FCAppController 里拿 tree、连信号、组 data、调 `bus->emitEvent`。  
   - 简化：把 tree 指针（或 getTree 的闭包）交给 FCPropertyPanelOperator，在 `setDockingArea`/`setTree` 里内部 connect(tree, geometryNodeSelected, ...) 并 emit 事件。  
   - 效果：Controller 少写一段 lambda，事件发送集中到协调者一侧；代价是协调者依赖“树存在”，略紧耦合。

2. **用 lambda 注册替代部分 Handler 类**  
   - 现在：每种类型一个 IPropertyPanelContentHandler 实现类（如 FCGeometryPropertyContentHandler）。  
   - 简化：协调者提供 `registerHandler(type, std::function<void(docking, nodeId)>)`，APP 里用 lambda 调用现有“几何内容创建逻辑”（可从 FCGeometryPropertyContentHandler 抽成自由函数或单例）。  
   - 效果：少一个 Handler 类文件，逻辑仍在；代价是复杂逻辑写在 APP 的 lambda 里会变长，可读性略差。

3. **保留总线、简化属性面板侧**  
   - 不搞协调者 + Handler 接口，改为**一个**“属性面板更新器”类订阅总线，内部 `switch(entityType)` 或 `if (entityType == Geometry) ... else if (Mesh) ...` 调用各类型的创建逻辑。  
   - 效果：少 IPropertyPanelContentHandler、少 registerHandler、只有一个订阅者；代价是每加一种类型都要改这个类的 switch，扩展性差一些。

4. **不做简化**  
   - 保持现状，用文档（本文档）和注释标清“事件从哪发、谁订阅、谁调 showContent”。  
   - 适合：确定会做多类型、多窗口联动，且希望“加类型只加文件、不改协调者”的团队。

### 7.3 建议

- **短期**：若 1～2 年内只会做几何 + 属性面板，可采用 7.2 中方案 3（一个更新器 + switch），或树直接连一个“几何属性连接器”，去掉总线与协调者。  
- **中长期**：若规划里已有网格/物理场/结果等且属性面板要随树切换，**当前“总线 + 协调者 + Handler”的复杂度是值得的**，不建议为省几层而牺牲扩展性；可只做 7.2 中方案 1（树→总线移入协调者），减少 Controller 里的胶水代码。
