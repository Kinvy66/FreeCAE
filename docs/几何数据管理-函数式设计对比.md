# 几何数据管理模块 vs 函数式几何设计指导文档 对比

本文档对比 **《函数式几何模块设计指导文档》** 与当前已实现的 **FCGeometryEntity**（及现有几何体系），并说明**已按设计文档补充**的函数式能力。

---

## 一、设计文档要求 vs 当前实现

| 设计文档要求 | 当前实现情况 | 缺口说明 |
|-------------|--------------|----------|
| **不保存中间几何实体，仅保存“几何操作节点”** | 现有 FCGeoCommandList 保存的是命令（FCAbsGeoCommand），但 FCGlobalGeoComponent 会保存 **member**（面/边/体索引）。FCGeometryEntity 只做“从当前几何 build 出实体视图”，不改变“是否存中间实体”的决策。 | 若严格按函数式：应**不保存** Face ID / Solid 等，仅保存操作类型+参数+依赖；当前仍依赖全局分组里的 member 索引。 |
| **支持修改中间步骤并自动重建** | 有撤销/重做，无“修改某一步参数 → 自动标记下游 → 仅重算受影响节点”。 | 缺 **Dirty 传播 + 局部重建**。 |
| **支持 DAG 依赖结构** | 命令列表多为顺序或树（Part 下有子命令），**无显式多输入 DAG**（如 Union(A,B) 的两输入依赖）。 | 缺 **DAG 结构**（多输入节点、邻接表、拓扑序）。 |
| **支持 Selection 规则（避免拓扑命名问题）** | FCGeometryEntity 提供的是 **实体 ID 列表**（Domain/Boundary/Edge/Point），ID 来自当前 build 的 member；**无“规则”**，重建后同一逻辑面可能变 ID。 | 缺 **Selection 规则系统**（Rule 在每次 build 时对当前形状求值，不依赖固定 ID）。 |
| **支持局部重建和缓存** | 无按节点缓存；每次从整棵命令树/全局分组重新生成实体视图。 | 缺 **每节点结果缓存** 与 **下游失效 + 局部重算**。 |
| **可扩展到 OCC 内核** | 几何实现已在 FCGeometryCommand（OCC）层；FCGeometryEntity 不依赖 OCC，只消费 FCGlobalGeoComponent。 | 已具备扩展点；若要做“规则选择”需在 OCC 层对 TopoDS_Shape 求值。 |

---

## 二、设计文档中的核心组件 vs 现状

### 2.1 几何节点与 DAG 管理器

**设计文档：**

- `GeoNode`：id, type, name, params, **inputs**（多输入）
- `GeometryTree`：nodes、adjacency、addNode、**topoSort()**

**现状：**

- `FCAbsGeoCommand`：单父/顺序或树形子命令，无通用 **inputs[]** 与 DAG 拓扑序。
- 无独立的 **GeometryTree / DAG 管理器**，无 **topoSort()**。

**仍缺：**

- 显式 **DAG**：多输入节点、邻接表、拓扑排序。
- 统一的 **GeoNode + ParamSet + inputs** 表示（可与现有 FCAbsGeoCommand 做映射或逐步替换）。

---

### 2.2 构建引擎

**设计文档：**

- `build()` = **topoSort()** → 按序 **applyNode()** → 结果写入 **nodeResults[id]**。
- 最终几何 = 某末节点在 nodeResults 中的形状。

**现状：**

- 几何由 FCGeometryCommand（OCC）按命令树执行生成，无统一的 **topoSort + applyNode + nodeResults** 管线。
- FCGeometryEntityBuilder 只从**已有** FCGlobalGeoComponent 填实体模型，不负责“执行 DAG”。

**仍缺：**

- 统一的 **构建引擎**：topoSort → 按序 applyNode → 每节点结果写入 nodeResults。
- **nodeResults** 缓存（int → TopoDS_Shape 或 FC 等价表示）。

---

### 2.3 修改中间步骤机制

**设计文档：**

- 修改节点参数 → **markDirty(node)** → 递归 **markDirty(下游)** → 只 **重算 dirty 节点**。

**现状：**

- 无 dirty 位、无下游依赖表、无“只重算受影响节点”。

**仍缺：**

- **Dirty 标记**与 **下游传播**（依赖 DAG 的 downstream 关系）。
- **增量/局部重建**（仅对 dirty 节点执行 applyNode 并更新 nodeResults）。

---

### 2.4 Selection 规则系统

**设计文档：**

- `SelectionRule::eval(shape)` → 返回形状列表；**每次重建后重新求值**，不依赖固定 Face ID。

**现状：**

- FCGeometryEntity 提供 **实体 ID**（Domain/Boundary/Edge/Point）和 getBoundariesOfDomain 等，无“规则”抽象。
- 选择依赖当前 build 的 member 索引，重建后 ID 可能变化。

**仍缺：**

- **SelectionRule** 接口（如 `eval(const TopoDS_Shape&)` 或 FC 的 shape 抽象）。
- 在 **每次 build 后** 用规则求值得到“当前选中的面/边/体”，供 Fillet 等操作使用，避免写死 Face ID。

---

### 2.5 缓存系统

**设计文档：**

- **nodeResults**：每个节点对应一个中间结果；节点变更时清除该节点及**下游**缓存。

**现状：**

- 无按节点缓存；FCGeometryEntityModel 是一次性从全局分组 build 出的“最终实体视图”，无中间节点级缓存。

**仍缺：**

- **nodeResults**（节点 ID → 几何结果）。
- **缓存失效策略**：改某节点 → 清空该节点及所有下游节点的缓存。

---

### 2.6 模块 API 风格

**设计文档：**

- `addBlock(...)`, `addUnion(int a, int b)`, `addFillet(int input, SelectionRule rule)`；
- `updateNode(int id, ParamSet p)`；`build()`。

**现状：**

- 通过 FCGeoInterfaceFactory 等创建命令并 append 到 FCGeoCommandList，无统一的 **GeometryModule** 风格 API，也无 **updateNode(id, params)** 与 **SelectionRule** 参数。

**仍缺：**

- 统一的 **GeometryModule** 式 API（add*、updateNode、build），以及 **Fillet 等操作接受 SelectionRule 而非固定 ID**。

---

## 三、FCGeometryEntity 已覆盖的内容（相对“实体视图”部分）

- **实体层级**：Domain / Boundary / Edge / Point 与 getDomainIds、getBoundaryIds、getEdgesOfBoundary 等（对应设计文档中“下游使用几何”的层级，而非“函数式 DAG”本身）。
- **一次 Build 的实体视图**：从当前几何（FCGlobalGeoComponent）生成 FCGeometryEntityModel，供网格/物理按实体选。
- **与 FCGlobalData 集成**：GDTGeomEntity 槽位、工厂中创建并写入实体模型。
- **与现有几何衔接**：Builder 从 FCGeoCommandList / FCGlobalGeoComponentManager 读入，不替代现有命令体系。

这些满足的是 **“运行期几何实体视图”** 和 **geometry-entity-module-design.md** 的目标，**不实现**《函数式几何模块设计指导文档》中的 DAG、规则、缓存、局部重建等。

## 四、已按设计文档在 FCGeometryEntity 中实现的功能（2026 年补充）

在 **FCGeometryEntity** 模块中已新增以下内容，与《函数式几何模块设计指导文档》对齐：

1. **DAG 结构**  
   - **FCGeoOpType**：Block / Cylinder / Sphere / Union / Difference / Intersection / Fillet / Chamfer / Import / Extrude / Revolve / Sweep。  
   - **FCGeoNode**：id, type, name, **params**（FCGeoParamSet = QMap<QString,QVariant>）, **inputs**（QList<int> 多输入）。  
   - **FCGeometryTree**：nodes、addNode/removeNode/setNode、**topoSort()**、**getDownstream(id)**、**getDownstreamRecursive(id)**（供 dirty 传播）。

2. **构建引擎**  
   - **FCGeometryBuildEngine**：setTree、setExecutor（OCC 层注入）、**build()** = topoSort → 按序 applyNode → 写入 **nodeResults**；**nodeResult(id)** 查询缓存。

3. **Dirty 与局部重建**  
   - **markDirty(nodeId)**：将该节点及**所有下游**加入 dirty 集合。  
   - **invalidateDownstream(nodeId)**：清除该节点及下游的 nodeResults。  
   - **buildDirty()**：仅对 dirty 节点执行 applyNode 并更新 nodeResults，然后清空 dirty。

4. **Selection 规则系统**  
   - **FCSelectionRule**：抽象接口 **eval(const QVariant& shape)** 返回 QList<QVariant>（选中子形状）；形状用 QVariant 传递，OCC 层可包装 TopoDS_Shape。  
   - **FCGeometryBuildEngine::setSelectionRuleForNode(nodeId, rule)**：为 Fillet 等节点绑定规则；执行时通过 **FCGeometryNodeExecutor::execute(node, nodeResults, selectionRule)** 传入。

5. **按节点缓存与失效**  
   - **nodeResults**：QHash<int, QVariant>，applyNode 后写入。  
   - 修改节点后调用 **invalidateDownstream** + **markDirty**，后续 **buildDirty()** 只重算受影响节点。

6. **GeometryModule 风格 API**  
   - **FCGeometryModule**：**addBlock(params)**、**addCylinder**、**addSphere**、**addUnion(a,b)**、**addDifference(a,b)**、**addIntersection(a,b)**、**addFillet(input, rule, params)**、**addImport(params)**、**updateNode(id, params)**、**build()**、**buildDirty()**；内部持有 FCGeometryTree 与 FCGeometryBuildEngine。

7. **可扩展到 OCC 内核**  
   - **FCGeometryNodeExecutor**：抽象接口 **execute(node, nodeResults, selectionRule)**、**supports(type)**；由 FCGeometryCommand（OCC）实现，将 nodeResults 中的 QVariant 解释为 TopoDS_Shape 并执行对应操作。

**仍可进一步强化的点**（与现有对象式几何并存时）：  

- **“仅存操作不存实体”**：若完全采用函数式流程，则不再依赖 FCGlobalGeoComponent 的 member 作为持久化；当前 DAG + build 结果仅缓存在 nodeResults 中，不写回 FCGlobalGeoComponent。  
- **与 FCGeometryEntityModel 联动**：在 build/buildDirty 完成后，可用最终形状或 nodeResults 更新 **FCGeometryEntityModel**（Domain/Boundary/Edge/Point），供网格/物理使用；可由上层在 buildFinished 信号中调用 FCGeometryEntityBuilder 或类似逻辑完成。

---

## 五、建议实现顺序（若要向函数式设计靠拢）

1. **DAG 层**：在现有命令之上或旁边引入“几何 DAG”（GeoNode + inputs、GeometryTree + topoSort），与 FCAbsGeoCommand 做映射或逐步迁移。
2. **构建引擎 + 缓存**：实现 topoSort → applyNode → nodeResults；节点参数变更时 markDirty + 下游传播，只重算 dirty 并更新缓存。
3. **Selection 规则**：定义 SelectionRule，在 build 后对当前形状求值；Fillet 等操作改为接受 Rule 而非固定 ID。
4. **与 FCGeometryEntity 联动**：在每次（局部或全局）build 完成后，用当前最终形状或 nodeResults 更新 FCGeometryEntityModel（或触发 FCGeometryEntityBuilder 重建），使实体视图与函数式 DAG 结果一致。

这样，**新增的几何数据管理模块（FCGeometryEntity）** 负责“实体视图与选择 API”，**函数式设计文档** 中的 DAG、规则、缓存、局部重建可在上游或并行模块中逐步补齐，二者共同构成完整的几何数据管理能力。
